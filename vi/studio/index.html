Cấu hình môi trường, Git và dự án trước khi bắt đầu làm việc. Mở rộng một chương để chuyển tới từng bước cụ thể.

01

NocoBase Studio

Cài đặt và khởi động NocoBase Studio để chuẩn bị môi trường cộng tác cho các agent.

1.1Chuẩn bị server

Chuẩn bị một server có thể truy cập npm, Docker registry và dịch vụ Git.

1.2Cài đặt và triển khai

Ví dụ này dùng tên miền và đường dẫn triển khai giả định. Hãy thay IP server, thư mục và tên miền trước khi chạy.

Prompt triển khai
Connect over SSH to root@YOUR_SERVER_IP and install and deploy NocoBase Studio.

Deployment configuration:
- Docker image: pkg-v3.nocobase.com/nocobase/studio:latest
- Registry token: provided privately
- Deployment directory: /root/deploy/apps/studio
- Public URL: https://studio.example.com/main/
- Studio base path: /main
- Existing Caddy Compose file: /root/deploy/docker-compose.yml

Requirements:
1. Inspect existing deployments, Docker networks, and Caddy configuration first, without disrupting other services.
2. For an existing Studio instance, preserve the database, uploads, and administrator account. For a new installation, use nocobase as the administrator, generate a random password, and save it in a server configuration file with mode 600.
3. Configure persistent storage, automatic container restarts, and Caddy reverse proxying with HTTPS.
4. Use unique container names and network aliases to avoid conflicts with other Studio instances.
5. Use the same /main site URL for Studio, the CLI, agents, and repository CI. Update Git callbacks and webhook URLs accordingly.
6. Verify container health, HTTPS access, administrator sign-in, and data persistence after a restart.
7. Report the deployed version, URL, configuration file locations, how to retrieve the password, and verification results.
Dùng URL đầy đủ của site ở mọi nơi

Điểm truy cập Studio trong ví dụ này là https://studio.example.com/main/. Dùng địa chỉ này cho CLI, kết nối máy tính, runtime và CI, bao gồm cả /main.

Sẵn sàng khiHTTPS hoạt động, quản trị viên đăng nhập được, và dữ liệu vẫn còn sau khi khởi động lại container.

02

Runner Agent

Thêm runtime, đặt mức đồng thời, bật các agent mà Runner dùng, và chọn agent thực thi cho project manager.

2.1Cấu hình runtime

Mở Agent management → Runtimes và nhấp Add runtime. Runtime có thể chạy trên máy tính của bạn hoặc trên server; khuyến nghị dùng máy ảo cô lập.

  1. Chọn Personal hoặc Shared và chọn các công cụ lập trình có sẵn trên host.
  2. Runtime mới mặc định cho phép 3 lần chạy đồng thời. Đặt Max concurrent runs phù hợp với tài nguyên của host và giới hạn của model. Ví dụ, nhập 10 để cho phép tối đa mười lần chạy cùng lúc.
  3. Nhấp Generate install command và sao chép lệnh do phiên bản Studio hiện tại của bạn tạo ra.

Mỗi hệ điều hành đều có hai cách cài đặt Prompt và Manual. Sao chép prompt cho một agent trên host đích, hoặc tự chạy lệnh đăng ký dùng một lần. Với Windows, prompt đầy đủ trước tiên yêu cầu agent kiểm tra xem mình có đang chạy trong WSL Ubuntu không. Nếu không, agent phải dừng lại và yêu cầu người dùng chạy wsl --install trong PowerShell, khởi động lại Windows, rồi mở lại agent trong WSL Ubuntu và chạy lại prompt. Chỉ khi ở trong WSL Ubuntu agent mới được tiếp tục; cài Node.js 24 và các công cụ lập trình bên trong WSL, bật mirrored networking nếu không truy cập được internet. Runtime cá nhân chỉ thực thi task của chủ sở hữu; runtime dùng chung thực thi task của bất kỳ người dùng nào, với biến và secret của người đó. Hãy dùng môi trường cô lập cho cả hai phạm vi: agent có toàn quyền truy cập và runner không phải là sandbox. Xác nhận kết nối bằng nocobase-runner status. Nếu không phát hiện công cụ nào, hãy chạy lại nocobase-runner service install trong một terminal mà which codex / which claude hoạt động, rồi khởi động lại service để ghi nhận PATH. Prompt cũng đề cập đến proxy, quyền npm global và việc tránh dùng gói snap.

2.2Bật agent

Khi runtime đã online, mở Agent management → Agents. Nhấp Fill in and enable cho một agent được phát hiện, hoàn tất cấu hình và bật nó để Runner dùng khi thực thi task.

Đồng thời cấu hình agent thực thi cho Project manager: chọn một agent khả dụng trong The agent it runs with → First choice, tùy chọn chọn thêm phương án dự phòng, rồi lưu.

03

Git

Cấu hình quyền truy cập repository và tài khoản Git cá nhân cho các dự án và đóng góp code.

3.1Cấu hình kết nối Git toàn cục

Vị trí: Settings → Integrations → Git. Kết nối Git toàn cục cho phép Studio truy cập GitHub hoặc GitLab và làm việc với các repository code.

Nhấp Add connection, chọn GitHub hoặc GitLab và làm theo các bước ủy quyền. Chọn kết nối này khi tạo dự án; việc tạo repository mới còn cần quyền tạo repository.

3.2Cấu hình tài khoản Git cá nhân

Vị trí: Account settings → Integrations → Git. Kết nối tài khoản Git của chính bạn để gắn các đóng góp code với danh tính của bạn.

04

Dự án

Tạo một dự án kết nối với repository, sau đó cấu hình CI workflow và thông tin xác thực triển khai.

4.1Tạo dự án

Cấu hình kết nối Git toàn cục trước. Mở Projects → New project và nhập tên dự án. Hướng dẫn này dùng New repository.

Chọn tài khoản hoặc tổ chức sở hữu repository, nhập tên và chế độ hiển thị, rồi chọn template khởi tạo và agent thực thi khi cần. Xem lại cấu hình và tạo dự án.

4.2Cấu hình CI

Nếu chưa cấu hình CI khi tạo dự án, hãy mở Settings → Deployment của dự án, nhấp Set up CI và làm theo hướng dẫn.

Chọn trigger, môi trường đích, thư mục ứng dụng và App ID. Với preview cho PR, chọn Pull request và Preview; dùng . cho Directory khi ứng dụng nằm ở thư mục gốc của repository.

  1. Thêm workflow do hướng dẫn cung cấp vào repository Git của bạn, ví dụ .github/workflows/nb-studio-test-preview.yml. Dùng nội dung do giao diện hiện tại của bạn tạo ra.
  2. Nhấp Generate key and show it once và sao chép deployment key CI cho repository này.
  3. Trong repository GitHub, mở Settings → Secrets and variables → Actions và thêm một Repository secret: đặt Name là NB_STUDIO_API_KEY và Secret là key bạn vừa sao chép.
  4. Commit workflow và kích hoạt hoặc chạy lại CI. Xác nhận build và triển khai thành công, rồi quay lại Studio để kiểm tra kết quả được báo cáo và mở bản preview.
Chỉ cần cấu hình thông tin xác thực một lần

Các lần chạy CI sau sẽ tự động đọc secret đã lưu. Hãy cập nhật khi key được xoay vòng, bị thu hồi hoặc hết hạn; tạo key thay thế cũng đòi hỏi cập nhật repository secret. Thiết lập thủ công trên trình duyệt này không cần cài Studio CLI trên máy tính của bạn.

05

Issue

Tạo issue thông qua Runner Agent hoặc My agents, theo dõi tiến độ, và review kết quả bàn giao cùng bản preview trong chi tiết issue.

5.1Tạo issue

Thông qua Runner Agent

Nếu chưa cấu hình My agents, hãy nhờ một Runner Agent sắp xếp yêu cầu. Nhấp New issue trong dự án và mô tả mục tiêu cùng công việc cần hoàn thành.

Thông qua My agents

Kết nối máy tính của bạn trước. Trong My agents hoặc bảng hội thoại tạo issue mới, nhấp Connect your computer, sao chép hướng dẫn và để một Coding Agent trên máy tính đó hoàn tất cài đặt và ủy quyền qua trình duyệt.

Khi máy tính đã online, nhấp New issue để mở một hội thoại My agent. Thảo luận yêu cầu, thống nhất phạm vi và tạo issue ngay trong hội thoại đó.

5.2Theo dõi issue

My issues

Dùng My issues để tìm công việc bạn phụ trách hoặc cần theo dõi, rồi mở một issue để tiếp tục.

My agents

Quay lại một hội thoại có sẵn trong My agents để tiếp tục thảo luận issue và xem công việc gắn với hội thoại đó.

Issue

Dùng Issues để duyệt danh sách issue, tìm công việc theo dự án hoặc trạng thái, và mở chi tiết.

5.3Chi tiết issue

Khi công việc bắt đầu, issue sẽ đi qua luồng thực thi. Dùng phần chi tiết để xem giai đoạn hiện tại, lịch sử thực thi và kết quả bàn giao.

Đang thực hiện

Kiểm tra giai đoạn thực thi hiện tại và hoạt động của agent để biết việc gì đang được xử lý.

Đang review

Khi issue đến bước review, hãy đọc báo cáo bàn giao và kết quả kiểm chứng, đồng thời kiểm tra các yêu cầu nghiệm thu. Thêm phản hồi cụ thể vào issue nếu cần thay đổi.

Môi trường preview

Sau khi CI của dự án triển khai thành công, mở ứng dụng từ bản preview được liên kết với issue và kiểm tra các trang cùng hành vi của nó.

06

Studio CLI

Quản lý dự án và issue trên Studio từ một Coding Agent cục bộ và điều tra các vấn đề phức tạp hơn.

6.1Cài đặt và kết nối

Cài Studio CLI nếu bạn muốn quản lý Studio từ một agent cục bộ. Nhấp vào ảnh đại diện ở góc trên bên phải, chọn Use Studio in your agent, và sao chép hướng dẫn thiết lập do phiên bản Studio hiện tại của bạn tạo ra.

  1. Máy tính của bạn cần Node.js 24 trở lên và npm. Đưa hướng dẫn thiết lập cho Coding Agent cục bộ.
  2. Làm theo hướng dẫn trên terminal để chấp thuận đăng nhập trên trình duyệt và xác nhận phiên bản Studio đích.
  3. Sau khi đăng nhập, kiểm tra danh tính và quyền, đọc tài liệu lệnh và cài CLI skill.
Kiểm tra sau khi đăng nhập
nb-studio whoami
nb-studio docs
nb-studio skills install
Dùng hướng dẫn từ site hiện tại của bạn

Ảnh chụp màn hình cho biết vị trí các control. Liên kết cài đặt và thông tin xác thực tạm thời có thể hết hạn, vì vậy hãy sao chép hướng dẫn mới từ trang hiện tại.

6.2Phân tích issue bằng agent cục bộ

Sau khi kết nối, hãy nhờ agent cục bộ hỗ trợ các vấn đề phức tạp. Cung cấp liên kết issue và câu hỏi bạn muốn điều tra, ví dụ:

Prompt phân tích issue
https://studio.example.com/main/issues/YOUR_ISSUE_ID
Analyze what is wrong with this issue and how to address it. Analysis only; do not make changes.
✓

  • ✓Các agent mà Runner và project manager dùng đã được cấu hình
  • ✓Quyền truy cập Git toàn cục và tài khoản Git cá nhân đã được cấu hình
  • ✓Dự án được liên kết với đúng repository
  • ✓CI workflow và deployment secret đã được cấu hình và bản preview truy cập được
