01

NocoBase Studio

安装并启动 NocoBase Studio，为 Agents 准备好协作环境。

1.1准备服务器

准备一台能访问 npm、Docker 镜像仓库和 Git 服务的服务器。

1.2安装与部署

以下使用示例域名和部署路径；执行前替换服务器 IP、目录和域名。

部署提示词
请通过 SSH 登录 root@YOUR_SERVER_IP，安装并部署 NocoBase Studio。

部署配置：
- Docker 镜像：pkg-v3.nocobase.com/nocobase/studio:latest
- 镜像仓库 Token：通过私密方式提供
- 部署目录：/root/deploy/apps/studio
- 访问地址：https://studio.example.com/main/
- Studio 部署路径：/main
- 现有 Caddy Compose 文件：/root/deploy/docker-compose.yml

部署要求：
1. 先检查现有部署、Docker 网络及 Caddy 配置，避免影响其他服务。
2. 如果已有 Studio 实例，保留数据库、上传文件和管理员账号；如果是首次部署，管理员使用 nocobase，生成随机密码并保存到权限为 600 的服务器配置文件中。
3. 配置数据持久化、容器自动重启，以及 Caddy 反向代理和 HTTPS。
4. 使用独立的容器名称和网络别名，避免与其他 Studio 实例冲突。
5. 将 Studio、CLI、Agent 和仓库 CI 的站点地址统一为上述 /main 地址，并同步 Git 服务的回调与 Webhook 地址。
6. 完成后验证容器健康状态、HTTPS 访问、管理员登录，以及重启后的数据持久化。
7. 汇报部署版本、访问地址、配置文件位置、密码查看方式和验证结果。
统一使用完整的站点地址

本示例的 Studio 入口是 https://studio.example.com/main/。后续 CLI、电脑连接、Runtime 和 CI 配置均使用这个入口，保留 /main。

完成标志 HTTPS 可访问、管理员可登录，容器重启后数据仍保留。

02

Runner Agent

添加运行环境、设置并发数量，启用 Runner 使用的 Agent，并为项目经理选择执行 Agent。

2.1配置运行环境

进入 Agent management → Runtimes，点击 Add runtime。运行环境可以是个人电脑，也可以是服务器；建议使用隔离的虚拟机。

  1. 按使用范围选择 Personal 或 Shared，勾选机器上准备使用的 Coding tools。
  2. 新增运行环境的默认最大并发数为 3。调整 Max concurrent runs（最大并发运行数）。根据机器资源与模型额度设置，例如需要同时执行 10 个任务时填写 10。
  3. 点击 Generate install command，复制当前页面生成的命令。

每个系统都提供「提示词 / 手动安装」（Prompt / Manual）。可复制提示词给目标机器上的 Agent，或自行执行一次性注册命令。Windows 完整提示词首先要求 Agent 判断自己是否在 WSL Ubuntu 中；不在就停止，告知用户到 PowerShell 执行 wsl --install、重启 Windows，再到 WSL Ubuntu 中打开 Agent 重执行提示词。只有在 WSL Ubuntu 中才继续；Node.js 24 和编码工具都装在 WSL 内，无法访问外网时开启镜像网络。个人仅执行所属用户的任务；共享可执行所有用户的任务并收到其变量和密钥。无论哪种范围，都建议隔离运行：Agent 拥有完全权限，执行机不是沙箱。安装后用 nocobase-runner status 确认连接。未检测到工具时，在 which codex / which claude 可用的终端重新执行 nocobase-runner service install 并重启服务，让服务带上正确 PATH。提示词也会指导处理代理、npm 全局安装权限以及避免 snap 版工具。

2.2启动 Agents

运行环境在线后，进入 Agent management → Agents。为发现的 Agent 点击 Fill in and enable，完成配置并启用，供 Runner 执行任务时使用。

还需要给 Project manager 配置执行 Agent：在 The agent it runs with → First choice 选择可用 Agent，按需设置 Fallback，然后保存。

03

Git

配置全局仓库授权与个人 Git 账号，让项目和代码提交关联到正确的身份。

3.1配置全局 Git 连接

位置：设置 → 集成 → Git。全局 Git 连接让 Studio 能访问 GitHub/GitLab，并与代码仓库协作。

点击 Add connection，选择 GitHub 或 GitLab，按页面指引完成授权。创建项目时选择这个连接；如果准备新建仓库，还需要相应的仓库创建权限。

3.2配置个人 Git 连接

位置：个人设置 → 集成 → Git。连接自己的 Git 账号，用于代码提交时的账号身份信息。

04

项目

连接代码仓库创建项目，再配置 CI 工作流与部署凭据。

4.1创建项目

先完成全局 Git 连接。进入 Projects → New project，填写项目名称；本指南选择 New repository。

选择仓库所属账号或组织，填写仓库名称与可见性，并按需要选择初始化模板和执行 Agent。检查配置后创建项目。

4.2配置 CI

如果创建项目时没有配置 CI，进入项目的 Settings → Deployment，点击 Set up CI，按向导完成配置。

按需要选择触发方式、目标环境、应用目录和 App ID。PR 预览选择 Pull request 与 Preview；应用位于仓库根目录时，Directory 填 .。

  1. 在 Git 仓库添加向导提供的工作流，例如 .github/workflows/nb-studio-test-preview.yml。文件内容使用当前界面生成的版本。
  2. 点击 Generate key and show it once（生成密钥并显示一次），复制这个仓库的 CI 部署密钥。
  3. 在 GitHub 仓库打开 Settings → Secrets and variables → Actions，添加 Repository secret：Name 为 NB_STUDIO_API_KEY，Secret 为刚复制的密钥。
  4. 提交工作流，触发或重跑一次 CI。确认构建和部署成功，再回 Studio 查看上报结果并访问预览。
凭据通常只配置一次

后续每次 CI 会自动读取这个 Secret。只有密钥轮换、撤销或到期等情况才需要更新；重新生成密钥后，记得同步更新仓库 Secret。手动通过网页配置这些内容，不要求你的电脑安装 Studio CLI。

05

任务

通过 Runner Agent 或 My agents 创建任务，跟进执行进度，并在详情中审查交付与预览。

5.1创建任务

通过 Runner Agent

没有配置 My agents 时，可以让 Runner Agent 帮你整理需求。在项目中点击 New issue，描述目标和需要完成的工作。

通过 My agents

先连接个人电脑。在 My agents 或新建任务的会话面板中点击 Connect your computer，复制提示词，交给这台电脑上的 Coding Agent 完成安装与浏览器授权。

确认电脑在线后，再点击 New issue，打开的就是 My agent 会话。在会话里沟通需求、整理范围，并创建任务。

5.2跟进任务

My issues

从 My issues 查看自己负责或需要跟进的任务，打开条目继续处理。

My agents

从 My agents 返回已有会话，继续讨论任务并查看会话关联的工作。

Issues

从 Issues 查看任务列表，按项目或状态查找任务并进入详情。

5.3任务详情

任务开始后会按执行流程流转。在详情里查看当前阶段、执行记录和交付结果。

进行中

查看当前执行阶段和 Agent 的工作记录，了解任务正在处理什么。

待审查

任务进入待审查后，阅读交付说明与验证结果，并按验收要求检查。需要调整时，把具体反馈补充到任务中。

预览环境

项目 CI 部署成功后，从任务关联的预览入口打开应用，实际检查页面和功能。

06

Studio CLI

在本地 Coding Agent 中管理 Studio 的项目与任务，协助分析复杂问题。

6.1安装与连接

如果希望在本地 Agent 中操控 Studio，可以安装 Studio CLI。点击右上角头像，选择 Use Studio in your agent，复制当前站点生成的配置提示词。

  1. 本地需要 Node.js 24 或更高版本及 npm。将提示词交给本地 Coding Agent 执行。
  2. 按终端提示在浏览器完成登录授权，确认连接的是目标 Studio。
  3. 登录后检查身份与权限、阅读命令文档，并安装 CLI skill。
登录后的检查与配置
nb-studio whoami
nb-studio docs
nb-studio skills install
使用当前站点生成的指令

截图用于定位入口。安装链接和临时凭据可能过期，请复制当前页面的新指令。

6.2让本地 Agent 分析任务

连接后，一些复杂的问题可以交给本地 Agent 协助。把任务链接和需要分析的问题一起提供，例如：

任务分析提示词
https://studio.example.com/main/issues/YOUR_ISSUE_ID
帮我分析一下这个任务是什么问题，要怎么处理，只分析，不改动。
✓

开始协作前，逐项确认

  • ✓Studio 可访问、能登录且数据持久化
  • ✓Runtime 在线，并发数量已按需配置
  • ✓Runner 使用的 Agent 与项目经理已配置
  • ✓全局 Git 连接与个人 Git 账号已配置
  • ✓项目已关联正确的代码仓库
  • ✓CI 工作流与部署 Secret 已配置，预览可访问
  • ✓能创建任务、跟进状态并审查交付
  • ✓按需连接 My agents 或安装 Studio CLI
