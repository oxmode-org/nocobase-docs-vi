# NocoBase 3 Docs

> NocoBase is the open-source platform for building, running, and evolving business systems with AI. Agents write the business code, NocoBase provides the foundation and governance, and people set goals and make the decisions.

## Getting started

### Introduction

- [What is NocoBase 3](https://docs.nocobase.com/getting-started/what-is-nocobase.md): NocoBase 3 is the open-source platform for building, running, and evolving business systems with AI, with an application foundation, development governance, and customizable business apps.

### Hands-on

- [Develop your first app](https://docs.nocobase.com/getting-started/develop-your-first-app.md): Create and start a NocoBase app, develop customer management with an agent, check permissions, and keep iterating.
- [Collaborate with Studio](https://docs.nocobase.com/getting-started/collaborate-with-studio.md): Submit a request in Studio, follow Agent handoffs and reviews, accept the result, and deliver a release.

### More

- [Learning path](https://docs.nocobase.com/getting-started/learning-path.md): Explore the documentation map and reading routes for applications, Studio, complete projects, and deployment.

- [Querying and manipulating data](https://docs.nocobase.com/core/developing-apps/querying-data.md): Use Repositories for business records, relations, pagination, transactions and bulk operations, and decide when to use Query.
- [Transactions and data consistency](https://docs.nocobase.com/core/developing-apps/transactions-and-consistency.md): Define service transaction boundaries and verify rollback, concurrency and cross-connection or external effects.
- [Multiple database connections](https://docs.nocobase.com/core/developing-apps/multiple-databases.md): Configure named connections, organize their migrations and Seeds, and select connections explicitly at runtime.
- [Connect an existing database](https://docs.nocobase.com/core/developing-apps/existing-databases.md): Connect to an externally managed schema, supply metadata and relations, and verify naming and access permissions.
- [Write application commands](https://docs.nocobase.com/core/developing-apps/application-commands.md): Write AppCommand classes in cli/commands, access application services, handle paths and JSON output, and verify commands in a deployment.
- [Integrate plugin commands](https://docs.nocobase.com/core/developing-apps/plugin-commands.md): Register existing plugin commands through cli/plugins.ts and verify namespaces, development commands, build hooks and deployment behavior.
- [Provide an application CLI client](https://docs.nocobase.com/core/developing-apps/cli-client.md): Give an application a standalone CLI using app-cli-client, connect to server business APIs, and test and package it for distribution.
- [Application configuration (config.yml)](https://docs.nocobase.com/core/developing-apps/configuration-and-settings.md): Modify config.yml, understand client and server code configuration, and add a configuration section with overrides, validation and public fields.
- [Testing](https://docs.nocobase.com/core/developing-apps/testing-and-acceptance.md): Test components, APIs, commands, and databases, then verify the UI and complete workflows with Playwright, an Agent, and manual checks.

## Tutorials

### Getting started

- [Build reliable enterprise apps with NocoBase 3](https://docs.nocobase.com/guides/build-reliable-enterprise-apps.md): NocoBase Core is the open-source foundation for developing and running business systems with AI, and NocoBase Studio is the governance platform where people and agents develop together.
- [Prepare your development environment](https://docs.nocobase.com/guides/prepare-environment.md): Install Node.js 24, pnpm 11.7 and Git, and set up WSL if you're on Windows.
- [Choose an agent and a model](https://docs.nocobase.com/guides/choose-agent-and-model.md): Pick a coding tool and a model.

### Part 1: Build an app with Core

- [Create the app](https://docs.nocobase.com/guides/create-app.md): Have the agent create a NocoBase app with SQLite in an empty directory, sign in, get to know the AGENTS.md, rules, skills and App foundation it comes with, and make the first Git commit.
- [Write a system design document first](https://docs.nocobase.com/guides/write-a-design-doc.md): Talk ITAM's design through with the agent and keep the design document in the repository, then describe every later request in business terms, covering who uses it, what to do and what the rules are.
- [First feature: the device register](https://docs.nocobase.com/guides/first-feature-devices.md): Have the agent build the device register from the design document, try it in the running app, and ask for changes.
- [Device requests and approval](https://docs.nocobase.com/guides/requests-and-approval.md): Employees submit device requests, the ones that need approval go to an asset manager, and IT support issues the device and records it in the register; the workflow and notifications use Core's ready-made workflow and notification plugins.
- [Roles and permissions](https://docs.nocobase.com/guides/roles-and-permissions.md): Sign in with each of the three accounts and check against the design document's permission matrix, so employees see only their own data, buttons follow the role, and the API refuses the same overreach.
- [Accept the agent's work](https://docs.nocobase.com/guides/accept-agent-work.md): Using a "needed by" date on device requests as the example, run it yourself with existing data, and send it back with steps to reproduce and the expected result when something is wrong.
- [Deploy the app](https://docs.nocobase.com/guides/deploy.md): Have the agent build an itam-lite image with the app's own Dockerfile and run it on a server with Docker Compose; configuration, data and the image are kept apart, and once live the app runs on its own.

### Part 2: Use Studio in a team

- [Bring the project into Studio](https://docs.nocobase.com/guides/bring-into-studio.md): Bring itam-lite into NocoBase Studio so the agent team can carry it forward.
- [Hand a request to the agent team](https://docs.nocobase.com/guides/agent-team-request.md): Use the device stocktake request to walk an issue through its whole flow in Studio, from raising it, starting, assigning and answering questions to checks and review, acceptance and merging.
- [Bring business colleagues in](https://docs.nocobase.com/guides/business-colleagues.md): Invite the asset manager to Studio, where they raise requests in business language in My sessions and answer questions, make decisions and accept results in My issues, without installing an agent.
- [Capture methods and experience](https://docs.nocobase.com/guides/capture-knowledge.md): Put the asset management policies in the knowledge base, write the ITAM checklist as a skill and look at what agents noted in project memory, so the background and methods survive a change of person or agent.
- [Release to production](https://docs.nocobase.com/guides/release.md): Using the device stocktake launch as the example, deploy to the staging environment Studio hosts after merging so the team can try it first, pick this release's issues from those pending release and tag it in the repository, then deploy to your own server with Studio's deployment guide and record the version production runs.
