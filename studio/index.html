01

NocoBase Studio

Install and start NocoBase Studio to prepare a collaboration environment for your agents.

1.1Prepare the server

Prepare a server that can access npm, Docker registries, and Git services.

1.2Install and deploy

This example uses a placeholder domain and deployment path. Replace the server IP, directory, and domain before running it.

Deployment prompt
Connect over SSH to root@YOUR_SERVER_IP and install and deploy NocoBase Studio.

Deployment configuration:
- Docker image: pkg-v3.nocobase.com/nocobase/studio:latest
- Registry token: provided privately
- Deployment directory: /root/deploy/apps/studio
- Public URL: https://studio.example.com/main/
- Studio base path: /main
- Existing Caddy Compose file: /root/deploy/docker-compose.yml

Requirements:
1. Inspect existing deployments, Docker networks, and Caddy configuration first, without disrupting other services.
2. For an existing Studio instance, preserve the database, uploads, and administrator account. For a new installation, use nocobase as the administrator, generate a random password, and save it in a server configuration file with mode 600.
3. Configure persistent storage, automatic container restarts, and Caddy reverse proxying with HTTPS.
4. Use unique container names and network aliases to avoid conflicts with other Studio instances.
5. Use the same /main site URL for Studio, the CLI, agents, and repository CI. Update Git callbacks and webhook URLs accordingly.
6. Verify container health, HTTPS access, administrator sign-in, and data persistence after a restart.
7. Report the deployed version, URL, configuration file locations, how to retrieve the password, and verification results.
Use the complete site URL everywhere

The Studio entry point in this example is https://studio.example.com/main/. Use this address for the CLI, computer connections, runtimes, and CI, including /main.

Ready whenHTTPS works, the administrator can sign in, and data survives a container restart.

02

Runner Agent

Add a runtime, set its concurrency, enable the agents used by the Runner, and select an execution agent for the project manager.

2.1Configure a runtime

Open Agent management → Runtimes and click Add runtime. A runtime can run on your computer or a server; an isolated virtual machine is recommended.

  1. Choose Personal or Shared and select the coding tools available on the host.
  2. New runtimes default to 3 concurrent runs. Set Max concurrent runs to match the host resources and model limits. For example, enter 10 to allow up to ten simultaneous runs.
  3. Click Generate install command and copy the command generated by your current Studio instance.

Each system offers Prompt and Manual installation. Copy the prompt to an agent on the target host, or run the one-time registration command yourself. The full Windows prompt first requires the agent to check that it is inside WSL Ubuntu. Otherwise it must stop and ask the user to run wsl --install in PowerShell, restart Windows, then reopen the agent in WSL Ubuntu and run the prompt again. Only inside WSL Ubuntu may it continue; install Node.js 24 and coding tools inside WSL, enabling mirrored networking if internet access fails. Personal runtimes execute only their owner’s tasks; shared runtimes execute any user’s tasks with their variables and secrets. Use an isolated environment for either scope: agents have full access and the runner is not a sandbox. Confirm the connection with nocobase-runner status. If no tools are detected, run nocobase-runner service install again in a terminal where which codex / which claude works, then restart the service to capture PATH. The prompt also covers proxies, npm global permissions and avoiding snap packages.

2.2Enable agents

Once the runtime is online, open Agent management → Agents. Click Fill in and enable for a discovered agent, complete its configuration, and enable it for the Runner to use when executing tasks.

Also configure the execution agent for Project manager: select an available agent under The agent it runs with → First choice, optionally choose a fallback, and save.

03

Git

Configure repository access and your personal Git account for projects and code contributions.

3.1Configure a global Git connection

Location: Settings → Integrations → Git. A global Git connection lets Studio access GitHub or GitLab and work with code repositories.

Click Add connection, choose GitHub or GitLab, and follow the authorization steps. Select this connection when creating a project; creating a new repository also requires repository creation permission.

3.2Configure your personal Git account

Location: Account settings → Integrations → Git. Connect your own Git account to associate code contributions with your identity.

04

Projects

Create a project connected to a repository, then configure its CI workflow and deployment credentials.

4.1Create a project

Configure the global Git connection first. Open Projects → New project and enter a project name. This guide uses New repository.

Choose the repository account or organization, enter its name and visibility, and select an initialization template and execution agent as needed. Review the configuration and create the project.

4.2Configure CI

If you did not configure CI when creating the project, open its Settings → Deployment, click Set up CI, and follow the guide.

Select the trigger, target environment, application directory, and App ID. For PR previews, choose Pull request and Preview; use . for Directory when the application is at the repository root.

  1. Add the workflow supplied by the guide to your Git repository, for example .github/workflows/nb-studio-test-preview.yml. Use the content generated by your current interface.
  2. Click Generate key and show it once and copy the CI deployment key for this repository.
  3. In the GitHub repository, open Settings → Secrets and variables → Actions and add a Repository secret: set Name to NB_STUDIO_API_KEY and Secret to the key you just copied.
  4. Commit the workflow and trigger or rerun CI. Confirm that the build and deployment succeed, then return to Studio to check the reported result and open the preview.
Configure the credential once

Subsequent CI runs read the stored secret automatically. Update it when the key is rotated, revoked, or expires; generating a replacement requires updating the repository secret too. This manual browser setup does not require Studio CLI on your computer.

05

Issues

Create issues through Runner Agent or My agents, follow their progress, and review the delivery and preview in issue details.

5.1Create an issue

Through Runner Agent

If My agents is not configured, ask a Runner Agent to organize the requirements. Click New issue in the project and describe the goal and work to complete.

Through My agents

Connect your computer first. In My agents or the new issue conversation panel, click Connect your computer, copy the instructions, and let a Coding Agent on that computer complete installation and browser authorization.

Once the computer is online, click New issue to open a My agent conversation. Discuss the requirements, agree on the scope, and create the issue in that conversation.

5.2Follow an issue

My issues

Use My issues to find work you own or need to follow up on, then open an issue to continue.

My agents

Return to an existing conversation in My agents to continue discussing an issue and view the work associated with the conversation.

Issues

Use Issues to browse the issue list, find work by project or status, and open its details.

5.3Issue details

Once work starts, the issue moves through its execution flow. Use its details to inspect the current stage, execution history, and delivery.

In progress

Check the current execution stage and agent activity to see what is being worked on.

In review

When an issue reaches review, read the delivery report and verification results and check the acceptance requirements. Add specific feedback to the issue if changes are needed.

Preview environment

After the project CI deployment succeeds, open the application from the preview linked to the issue and check its pages and behavior.

06

Studio CLI

Manage Studio projects and issues from a local Coding Agent and investigate more complex problems.

6.1Install and connect

Install Studio CLI if you want to manage Studio from a local agent. Click your avatar in the upper-right corner, select Use Studio in your agent, and copy the setup instructions generated by your current Studio instance.

  1. Your computer needs Node.js 24 or newer and npm. Give the setup instructions to your local Coding Agent.
  2. Follow the terminal instructions to approve sign-in in your browser and confirm the target Studio instance.
  3. After signing in, check your identity and permissions, read the command documentation, and install the CLI skill.
Checks after sign-in
nb-studio whoami
nb-studio docs
nb-studio skills install
Use instructions from your current site

The screenshots show where to find the controls. Installation links and temporary credentials can expire, so copy fresh instructions from your current page.

6.2Analyze an issue with a local agent

Once connected, ask your local agent to help with complex problems. Provide the issue link and the question you want investigated, for example:

Issue analysis prompt
https://studio.example.com/main/issues/YOUR_ISSUE_ID
Analyze what is wrong with this issue and how to address it. Analysis only; do not make changes.

  • ✓The project is linked to the correct repository
  • ✓The CI workflow and deployment secret are configured and previews are accessible
  • ✓You can create issues, follow their status, and review delivery
